# Архив отчётов Regions API

Все отчёты проекта хранятся здесь по дате прогона: `YYYY-MM-DD/BUG-NNN-*.md`.

BUG-001, BUG-002 и BUG-003 перенесены из прежней корневой папки `bug/` без
изменения содержимого. Они сохраняют исторические пользовательские наблюдения.
Новые агентские отчёты основываются только на текущем прогоне `agents-test/func/`
и контракте `tz-extracted.txt`; старые отчёты не используются как доказательства.
Архив можно читать для сохранения истории, выбора свободного BUG-ID и
предотвращения дубликатов.

Перед созданием нового отчёта проверь `.agents/skills/regions-api-bug-reporting/SKILL.md`.
Классифицируй каждое наблюдение как подтверждённое нарушение контракта,
неподтверждённое ожидание, проблему теста или инфраструктурную ошибку.

## Группировка результатов

Создавай один отчёт на одну установленную первопричину, а не отдельный отчёт
на каждый упавший pytest-кейс. Объединяй кейсы только при подтверждённой общей
причине; независимые причины оформляй раздельно. В отчёте перечисляй все
затронутые pytest node ID и результат каждого кейса. Для каждого падения
указывай ожидаемое и фактическое поведение. Если причина не подтверждена,
оформляй одно отдельное наблюдение и явно фиксируй неопределённость.

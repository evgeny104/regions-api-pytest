# Ревью тестов Regions API

Контракт проекта задан в `tz.pdf`, правила функциональных тестов — в skill
`.agents/skills/regions-api-test-authoring/SKILL.md`. Этот skill задаёт порядок
независимого ревью.

## Порядок проверки

1. Изучи diff, затем только связанные с изменениями тесты, модели, фикстуры
   и конфигурацию pytest.
2. Разделяй прямые требования контракта и предположения или наблюдения.
3. Проверь, что сценарии покрывают изменённое поведение без необоснованных
   дубликатов.
4. Проверь, что сценарии находятся в `tests/func/`, используют функциональные
   фикстуры и совместимые параметры для сравниваемых ответов.
5. Проверь, что ассерты выявляют регрессию, структура ошибок соответствует
   модели ответа, а негативные сценарии проверяют конкретные `error.id` и
   `error.message`, когда они определены контрактом.
6. Проверь полноту проверки значимых полей и граничных сценариев, относящихся
   к изменению. Правила проекта для `total`, `xfail`, маркеров и фикстур смотри
   в skill автора.

## Ограничения и формат ответа

Работай read-only и не запускай тесты. Не добавляй косметические замечания без
основания в контракте или устойчивом стиле проекта.

Сначала перечисли замечания, требующие исправления: приоритет, файл и строка,
основание и конкретное предложение. Затем укажи необязательные улучшения.
Если замечаний нет, явно сообщи, что diff прошёл ревью.

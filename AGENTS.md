# AGENTS.md

Инструкции для Codex в этом проекте. Подробное описание проекта, установка,
команды и структура приведены в `README.md`; здесь оставлены только правила,
важные для выполнения задач.

## Источники истины

- Контракт API: `tz.pdf`.
- Команды pytest и зарегистрированные маркеры: `pyproject.toml` и `README.md`.
- Функциональные фикстуры: `tests/func/conftest.py`.
- Навыки тестирования: `.agents/skills/`.

## Среда и проверки

- Работай из корня проекта и используй `.venv`.
- В PowerShell активируй окружение: `. .\.venv\Scripts\Activate.ps1`.
- Запускай `pytest`, не `python -m pytest`, чтобы проверять импорт так же, как CI.
- `pytest` и `pytest tests/func` запускают функциональные тесты и вызывают API.
- В проекте только функциональные API-тесты; unit-тесты не добавляй.
- Запускай тесты только по просьбе пользователя проверить изменения.
- Функциональные тесты запускай только по явной просьбе проверить стенд.
- Если `.venv` отсутствует, создай его командой `py -3.14 -m venv .venv`,
  затем установи зависимости через `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`.
- Если `.venv` повреждено, сначала проверь `py -3.14 --version`. При доступном
  Python 3.14 пересоздай окружение командой `py -3.14 -m venv --clear .venv`,
  затем установи зависимости из `requirements.txt`. В Codex отказ доступа к
  системному Python может потребовать запуска команды с повышенным доступом.
- Не устанавливай зависимости глобальным `pip`.

## Контракт и тесты

1. Перед тем как называть поведение API дефектом, проверь требование в `tz.pdf`.
2. Не ослабляй проверки ради зелёного CI. Подтверждённый дефект отмечай
   `pytest.mark.xfail(reason="BUG-XXX: …", strict=True)`.
3. По контракту `total` — общее число регионов и не меняется от фильтров.
   Не рассчитывай последнюю страницу от `total` при активном фильтре.
4. Используй существующие маркеры и фикстуры. Новый маркер сначала зарегистрируй
   в `pyproject.toml` и сообщи пользователю.

## Маршрутизация через агентов

- Для задачи на создание или изменение API-тестов делегируй реализацию
  `regions-test-author`.
- Для подготовки репорта о подтверждённом дефекте API поручай автору
  использовать skill `regions-api-bug-reporting` и сохранять файл в
  `bug/YYYY-MM-DD/`, где папка названа датой прогона.
- После готового diff тестов передай их `regions-test-reviewer` на независимое
  read-only ревью. Не запускай обоих одновременно на одних файлах.
- Для анализа без изменений автора не запускай; ограничения пользователя
  на тесты и сетевые проверки имеют приоритет.
